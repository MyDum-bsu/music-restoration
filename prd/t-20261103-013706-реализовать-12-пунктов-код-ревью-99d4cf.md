## Goal

Репозиторий проходит контракт код-ревью 2026-11-02: один скорер релизов, портируемые скиллы без машинных путей, тесты на агент-критичные парсеры, документированный вход (куки rutracker + Transmission), CI с pytest, версия >= 2.1, `CODING_STANDARDS.md`, шаблон `config/workspace.example.json`, `qc_gates --orig`, деприкейт `release_batch.py`, валидный YAML во frontmatter скиллов.

- Не трогать `/media/mydum/Data`, запущенные процессы, `config/workspace.json`, `~/.config/music-restoration/`.
- Не чинить найденные баги парсеров: тесты фиксируют текущее поведение, расхождение — отчёт, не правка.
- Не переносить `research/status_report.py` в `scripts/` и не менять `research/` (исправление — только текст скилла).
- Не добавлять линтеры/форматтеры/type-check в CI сверх pytest.
- Не удалять `scripts/release_batch.py` (только деприкейт).
- Не менять `rnext/rtclient.py`: скрипт обновления кук обязан обойтись существующим API.

## Use cases

1. Новый пользователь клонирует репозиторий, читает `docs/setup.md`, кладёт `config/workspace.example.json` → `config/workspace.json`, обновляет куки через `scripts/rt_browser_refresh.py`, запускает `restore this`. Скиллы не содержат путей этой машины, поэтому флоу не ломается.
2. Агент ранжирует релизы: и скилл-флоу (`rnext/planner`), и датасет-флоу (`scripts/tracker_hunt`) получают одинаковый порядок, потому что критерии живут в одном месте.
3. Владелец гоняет CI на PR: pytest на `tests/` краснеет на сломанном парсере, а не на живом прогоне реставрации.
4. Владелец реставрирует горячий мастер: `qc_gates --orig` не валит трек за спайки, которых в источнике было больше.
5. Разработчик, у которого остался старый вызов `release_batch.py`, получает явный deprecation-вывод и указание на `restore_per_track.py`.

## UX

- Скиллы: вместо `R=/media/...` — «путь из `config/workspace.json`» / значение из `rnext.workspace`. Текст остаётся исполняемым для агента: одна строка про источник пути, без машинных литералов.
- `scripts/rt_browser_refresh.py --help` объясняет: что нужно (браузер, вход на rutracker), что записывает (`cf_clearance` + UA в `~/.config/music-restoration/secrets/`), что делать при неудаче.
- `docs/setup.md`: линейный чек-лист «python/ffmpeg/flac → config/workspace.json → Transmission RPC → куки → первая реставрация», с точными путями и командой проверки.
- `scripts/release_batch.py`: при любом запуске в stderr — одна строка `DEPRECATED: ... use scripts/restore_per_track.py ...`, поведение скрипта не меняется.
- `qc_gates.py --orig <dir>`: в отчёте по спайкам видно и число в источнике, и в результате.

## Edge cases

- `config/workspace.example.json` не должен содержать ни одного машинного пути и должен парситься как JSON.
- Скилл может ссылаться на путь, которого нет (`scripts/status_report.py`) — проверка существования обязана поймать это и до, и после.
- Frontmatter скилла с двоеточием в значении (`description: A: B`) без кавычек — YAML-парсер должен падать; после фикса — проходить. Если PyYAML в окружении нет, используется минимальная проверка формы (см. oracle), чтобы контракт не зависел от установленного пакета.
- `qc_gates.py --help` без `--orig` должен работать как раньше; добавление флага не делает его обязательным.
- Пути в скиллах с глобами (`tests/fixtures/*.html`) и с `~/.config/...` не считаются ссылками на файлы репозитория и не проверяются на существование.
- Параллельный прогон реставрации во время работы: правки `qc_gates.py` не должны менять импортируемые имена и сигнатуры существующих функций.

## Risks

- **Параллельный конвейер.** `qc_gates.py` правится, пока идёт реставрация → только аддитивно, без переименований; риск средний, контролируется инвариантом I3 и ревью диффа.
- **Унификация скорера меняет ранжирование.** Датасет-флоу начнёт выбирать другие релизы → это цель пункта, но требует, чтобы `score_facts` покрывал оба набора критериев; иначе регресс качества выдачи. Контроль: `tests/` + явный diff критериев в PR.
- **Проверка «все пути в скиллах существуют» может вытащить много дрейфа.** Это и есть пункт 3; объём правок — текст скиллов, не код.
- **`--orig` может замаскировать реальный регресс** (гейт станет мягче). Контроль: FAIL остаётся при `restored > orig` и при `restored > absolute` в режиме без `--orig`.
- **CI может оказаться нерабочим** (нет зависимостей в workflow) → workflow обязан ставить зависимости из `pyproject.toml`/`requirements` и запускать `pytest tests/` без сети.
