# PRD — one-command album evaluation (restoration vs its source)

Task: `t-20261114-225449-цель-оценить-качество-альбома-6cea50`
Depends on: `t-20261104-235752-цель-оценить-насколько-наш-скил-7a46f8` (the measurement kernel).

## Goal

The operator restored an album and currently has no single honest answer to
"is it good?": `audio_measure` prints per-file diagnostics, `qc_gates` is a
per-file gate, `compare_restore` is hard-wired to the three-root INDEP
experiment, and the listening tools are research-side.  One command measures
the restored album against its own source, applies a verdict procedure declared
before the data, lifts the runner's own statuses (`restore_safe` report.json),
and renders a human report that separates proven facts from proxy limits.

## Non-goals

- Changing restoration DSP, gates or the runner — this evaluates the pipeline
  as it is.
- Judging listening preference: metrics are proxies; blind listening stays a
  separate, later loop (`scripts/listen_pack.py`).
- Corpus-scale comparisons vs masters — that is `scripts/eval_vs_masters.py`.
- Any statistical superiority claim; five handpicked albums are regressions,
  not holdouts.

## Use cases

1. **After a restore run.** `evaluate_album --src <orig> --restored <out>`
   → report says: dynamics raised (DR +N, crest +N), no added clipping or
   clicks, TP within ceiling on k/N tracks, loudness shifted by −X LU (by
   design), tonal shift +X dB (information), runner statuses: n processed /
   m kept original / needs_review k.
2. **A track regressed.** verdicts.csv shows `orig_better/dr` for that track
   and the report names it — the operator re-runs or keeps the original.
3. **Bonus track not covered.** The source has a track the restoration does
   not: it is listed as skipped with a reason in summary.json and REPORT.md,
   never silently dropped.
4. **Reviewer wants the raw rows.** tracks.csv carries every measured value;
   one re-run of `audio_measure.py` on one file reproduces any cell.

## UX

CLI only (pinned flags):

```
python3 scripts/evaluate_album.py --src DIR --restored DIR --out DIR \
        [--tp-ceiling -0.9] [--dr-threshold 0.3] [--loudness-mismatch-lu 2.0]
```

Exit codes: 0 success, 2 bad input (missing/empty dir, undecodable file,
missing metric) with the offending path on stderr and nothing written.

## Edge cases

- Same track numbers on both sides: matched by number.
- Numbers differ but normalized names (parentheticals stripped) match exactly:
  matched via name; ambiguous candidates stay unmatched with
  `ambiguous_name_match`.
- `report.json` missing: statuses are `unknown`, not fabricated.
- Mono files: the spike/band decode keeps native channels (the mono→stereo
  remix attenuates by −3 dB in this ffmpeg build and would hide full-scale
  spikes).
- A track whose band vector length differs between sides is a hard error
  (exit 2), never a silent mean.
