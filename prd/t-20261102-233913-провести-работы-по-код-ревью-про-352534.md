   только если спайков в выходе больше, чем в источнике; без `--orig` поведение

5. MEDIUM — тесты парсеров на сохранённых HTML-фикстурах:

6. MEDIUM — `docs/setup.md` + `scripts/rt_browser_refresh.py` (обновление

8. LOW — `CODING_STANDARDS.md`, CI с pytest (`.github/workflows/`),

## Use cases

1. Новый пользователь клонирует репозиторий на другую машину: `docs/setup.md`
   объясняет Transmission/RPC, куки и `config/workspace.json`; `config/workspace.example.json`
   даёт шаблон без `/media/mydum`, `/home/<user>`.
2. Агент по скиллу `tracker` сравнивает версии релиза и по скиллу `release-restore`
   выбирает пару «мастер → оригинал»: оба пути ранжируют качество одной функцией,
   «лучший» не расходится между флоу.
3. Горячий мастер (748 спайков в источнике, 35 в реставре): `qc_gates.py --orig`
   даёт PASS, потому что выход чище источника; без флага поведение прежнее.
4. Куки rutracker протухли, `rnext/rtclient.py` требует browser fallback:
   `scripts/rt_browser_refresh.py` обновляет `cf_clearance` по инструкции из
   `docs/setup.md`, без ручного копирования из DevTools.
5. Контрибьютор запускает CI: pytest на push/PR краснеет до того, как сломанный
   парсер доедет до `dev`.

  `config/workspace.example.json`, версия в `pyproject.toml` = 2.1.x.

## Edge cases

- `--orig` задан, но в источнике/DR-таблице источника спайков не посчитать
  (нет файла, нет колонки): гейт не должен молча PASS. Решение: считать baseline
  отсутствующим и падать с явной ошибкой, а не подставлять 0.
- Спайков в выходе ровно столько же, сколько в источнике → PASS (`>` строго).
- Спайков в источнике 0, в выходе 0 → PASS; в источнике 0, в выходе >0 → FAIL.
- Релиз без DR-таблицы в топике: `dr_published` отсутствует — скорер не меняет
  оценку, но и не падает; `score_facts` обязан вести себя как прежний `score`
  на всех неполных словарях фактов.
- Парсер получил HTML без ожидаемого блока (удалённый топик, капча): тест
  фиксирует поведение явно, а не «пустой словарь молча».
- Скилл ссылается на `research/status_report.py` — после сверки ссылка указывает
  на существующий файл; отсутствующий путь в скилле = красный oracle.
- `config/workspace.example.json` содержит машинные пути-примеры
  (`/media/<user>/Data`) — запрещены и в примере.
- Протухшие куки на другой машине: `rt_browser_refresh.py` без браузера/профиля
  завершается понятной ошибкой, а не тихим успехом.

## Risks

- **Живой конвейер.** `qc_gates.py` используется фоновой реставрацией прямо
  сейчас. Митигация: только новый опциональный флаг, дефолтный путь не меняется;
  `restore_per_track.py`/`finish_release.py` вне `allowed_paths`.
- **Ранжирование меняется.** Слияние скореров может изменить порядок версий на
  реальных топиках. Митигация: `score_facts` = перенос тела прежнего `score`
  без изменения весов; `score_candidate` сохраняет свою логику паросочетания;
  property-тест сравнивает делегацию с эталоном на граничных наборах фактов.
- **Скореры не эквивалентны по входу** (см. Open questions). Если попытаться
  свести `score_candidate` и `score` в одну функцию, сломается паросочетание
  мастер→оригинал. Спека фиксирует форму: одна реализация качества + тонкая
  делегация, паросочетание остаётся в planner.
- **Оракул статический там, где сигнатуры не зафиксированы** (парсеры): спека
  требует наличия тестов на фикстурах и зелёного `tests/`, а не конкретных
  ассертов — иначе оракул диктует реализацию.
- **Property-команда импортирует `scripts/tracker_hunt.py`**, а тот тянет
  bs4/requests/rnext.rtclient. На этой машине стек стоит; на голом python
  команда упадёт явной ошибкой импорта — это ожидаемо и не маскируется.
- **Скоуп широкий** (8 пунктов, 3 уровня). Митигация: пункты независимы, порядок
  в спеке фиксирован, `dod` один и проверяет все контракты сразу.

## Open questions

1. «Объединить два скорера» — это одна функция или одна реализация весов?
   Входы разные (`score_candidate(row, artist_tokens, ...)` — паросочетание
   мастер→оригинал по токенам/году/каталожному номеру; `score(facts)` — качество
   версии по разобранным фактам). Рекомендация спеки: в `rnext/planner.py`
   появляется `score_facts(facts) -> (float, list[str])` с телом прежнего
   `tracker_hunt.score`; `tracker_hunt.score` — делегация; `score_candidate`
   остаётся паросочетанием и при оценке качества вызывает `score_facts`.
   Сведение обеих в одну сигнатуру отклонено: сломает паросочетание.
2. `--orig` без baseline (нет спайков в источнике или нет источника):
   падать с явной ошибкой (рекомендация, соответствует «никаких фоллбэков»)
   или считать baseline = 0 и FAIL'ить по-старому? Спека фиксирует падение.
   Если владелец выберет иначе — меняется только текст ошибки/ветка в
   `qc_gates.py`, оракул на этот пункт — `--help` и наличие флага.
