# PRD — доказательное сравнение качества реставрации

## Goal

Ответить на вопрос «наш метод реставрации действительно лучше альтернативы
или мы просто измеряем себя собой?» так, чтобы ответ нельзя было отбросить:

- построить **независимый** метод реставрации (INDEP), не использующий
  `restore_per_track.py`, `rnext.dsp.pipeline` и их параметры;
- измерить ORIG / OURS (канон `[restored per-track]`) / INDEP одним
  нейтральным инструментом (`scripts/audio_measure.py` + ffmpeg);
- вывести вердикт по объявленной заранее процедуре с явными порогами;
- сдать отчёт с таблицами по треку и альбому, контрпримером и разделом
  «насколько сравнение вообще корректно».

Результат — три скрипта в `scripts/experiment/`, машиночитаемые данные и
отчёт в `docs/`, документ о методе. Всё воспроизводимо по сиду.

## Non-goals

- Не менять конвейер: `rnext/`, `scripts/*.py` верхнего уровня, `pyproject.toml`
  остаются как есть. Эксперимент живёт рядом, а не внутри.
- Не улучшать и не перезаписывать каноны, не трогать телефон, не изменять
  `release_src` (только чтение).
- Не давать субъективную оценку на слух: слепое прослушивание не проводится,
  и это прямо написано в отчёте.
- Не объявлять победителя по громкости: LUFS — метрика сравнимости, не
  качества.
- Не исправлять найденные дефекты канона в этой задаче: дефект идёт строкой в
  отчёт, правит его отдельная задача.
- Не строить ML-модель цели: INDEP — фиксированный DSP-метод с параметрами.

## Use cases

1. **Владелец решает, доверять ли канону.** Открывает
   `docs/experiment-independent-restore-2026-11-04.md`, читает `## Verdict` и
   `## Limitations`; за 2 минуты понимает, где канон выигрывает, где нет и
   насколько вывод вообще сравним.
2. **Ревьюер проверяет отсутствие круговой ссылки.** Читает
   `docs/experiment/independent-method.md`, смотрит `ref_restore.py`: другой
   код, другие ступени, нет импортов канона. Проверяется тестом, не глазами.
3. **Повтор прогона.** Через полгода: `manifest.json` хранит сид, отчёт хранит
   дословные команды; повтор даёт те же цифры (проверяется тестом на
   воспроизводимость метрик).
4. **Разбор одного трека.** Инженер берёт строку из `tracks.csv`, видит
   `band_delta_max_db` и `spikes_gt_0_9` и понимает, за счёт чего получен
   прирост DR.

## UX

Четыре команды, один каталог данных, один отчёт.

| шаг | команда | артефакт |
|---|---|---|
| выбор | `scripts/experiment/select_albums.py --src … --per-artist 5 --seed S --out manifest.json` | `manifest.json` |
| реставрация | `scripts/experiment/ref_restore.py --src … --out …` | 24-bit FLAC по треку |
| измерение | `scripts/experiment/compare_restore.py --src … --ours … --indep … --out-dir …` | 5 файлов данных + `tables.md` |
| отчёт | пишет агент | `docs/experiment-independent-restore-2026-11-04.md` |

Чтение отчёта: сначала таблица критериев (что считается лучше и с каким
порогом), затем вердикты по альбомам, затем контрпример, затем оговорки.
Каждое «лучше/хуже» стоит рядом с числом, из которого оно получено; строка
`loudness_mismatch` означает «DR сравнивать нельзя, громкости разные».

Ошибки говорят, что именно не так: имя трека, чего не нашлось, какой путь
запрещён. Молчаливых пропусков и «продолжим без этого трека» нет.

## Edge cases

- **`ebur128` не даёт LUFS/TP** (очень короткий трек, тишина, битый поток):
  ячейка пустая, `comparability=unknown`, вердикт по процедуре не зависит от
  LUFS. Пустая ячейка в `dr`/`crest`/`peak` недопустима — это падение.
- **Альбом есть в `--src`, но нет в `--ours` или `--indep`:** выход с кодом
  ≠ 0 и перечислением; частичный `tracks.csv` не пишется. Никаких «сравним,
  что есть».
- **Мультидиск:** ключ трека — путь внутри каталога альбома без суффикса
  (`CD1/01 - x`), поэтому одинаковые `01 - x` на разных дисках не склеиваются.
- **Разные входные форматы** (16/24 bit, 44.1/96 kHz, wav-источник): выход
  INDEP всегда FLAC 24 bit той же частоты; `bits`/`sr` есть в `tracks.csv`;
  сравнение DR валидно внутри трека, между треками — нет, это в `## Limitations`.
- **Источник без клиппинга:** INDEP всё равно нормализует к `-14 LUFS`, DR
  может упасть. Это ожидаемый контрпример, а не баг; он обязан попасть в
  `## Counterexamples`, если таких треков много.
- **Канон отсутствует у релиза, который есть в sources** (например, JP-релиз):
  альбом исключается из прогона и перечисляется в `## Limitations`.
- **Имя альбома содержит `[restored per-track]` в `--src`:** guardrail
  смотрит только на путь **записи**, чтение источников не блокируется.
- **Нехватка диска:** обработка по одному треку, WAV только во временном
  каталоге, удаление сразу после кодирования; `ENOSPC` → падение с явной
  ошибкой, а не отчёт по половине альбомов.
- **Округление DR до 2 знаков** и порог 0.3 dB: значения в вердикте берутся
  уже округлённые, чтобы вердикт не зависел от внутренней точности.

## Risks

| риск | чем плох | что делаем |
|---|---|---|
| круговая ссылка (INDEP повторяет канон) | весь отчёт ничего не доказывает | отдельный код + тест-грепалка на запрещённые импорты; документ «why it is independent» |
| вердикт только по DR | DR растёт при порче спектра и клиппинге | `band_delta_max_db`, `spikes_gt_0_9`, дисквалификация по TP > −0.9, обязательный `## Counterexamples` |
| перезапись канона или источника | потеря библиотеки | guardrails по путям, хэши `src` до/после в тесте, отчёт только читает канон |
| переполнение диска (~11G) | обрыв на середине, битые артефакты | по-трековая обработка, немедленная очистка, падение с явной ошибкой |
| долгий прогон (ffmpeg × 3 версии × ~20 альбомов) | часы | выбор ≤ 5 альбомов на автора, один проход по треку без повторных декодирований |
| ложное «одинаково» | порог 0.3 dB скрывает реальную разницу | порог объявлен в `## Criteria` как решение, а не как факт; в отчёте указано, какие разницы лежат ниже порога |
| «улучшение» за счёт громкости | сравнение несравнимого | `comparability=loudness_mismatch` при разнице LUFS > 2 |

## Verification plan

- `dod`: `python3 -m pytest .factory/integration/oracle/t-20261104-104731-цель-доказательное-сравнение-кач-519fb2/test_experiment_independent_restore.py -q`
  — 12 тестов: наличие и независимость скриптов, документ метода,
  сидированный выбор 5/автора, границы пика и клиппинга, целостность
  источников, guardrails путей, воспроизводимость метрик, схема CSV,
  совпадение ORIG-строк с `scripts/audio_measure.py`, вердикты по правилу
  (ветка `ceiling` обязана сработать), отказ на неполной тройке,
  согласованность закоммиченного отчёта с CSV, seeded-инварианты.
- Негативный корпус `oracle/negative/<id>/kit.patch` (passthrough-реставрация,
  выбор без сида, выдуманные числа): оракул обязан упасть на нём; какие тесты
  при этом обязаны пройти — в README корпуса.
- `properties` — 16 сидов по одному прогону на сид (инварианты: источники не
  тронуты, пик ≤ 0 dBFS-запас, метрики заполнены, дублей ключей нет,
  одинаковые входы дают `comparable/tie`).
- Ручная приёмка: отчёт читается без исходников, каждый альбом из
  `albums.csv` упомянут, `## Counterexamples` непустой, `TODO` нет.
- Реальный прогон по корпусу в этой сессии **не выполнялся** (нет доступа к
  `/media/...`): его делает воркер, и без него `test_real_report_and_data_are_consistent`
  красный. Это и есть гейт на «отчёт действительно есть».

## Open questions

1. Хранить INDEP-файлы после прогона или удалять? По умолчанию: удалить после
   измерения (несколько ГБ на 11G-диске), метрики + сид достаточны для повтора.
2. Включать в прогон релизы без канона (JP-релиз Perfect Plan)? По умолчанию:
   нет, исключить и перечислить в `## Limitations`. Если решение другое —
   Mismatched-пары придётся считать по ORIG↔INDEP отдельно, это +1 раздел
   отчёта, на гейт не влияет.
