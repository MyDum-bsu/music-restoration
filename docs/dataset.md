# Датасет пар «оригинал → реставрация» (два автора)

Документ описывает, как собирается обучающая выборка для пайплайна
`restore-next`: зачем она, из чего состоит, где хранится и как на ней
улучшается DSP-ядро.

## 1. Два автора — это два разных реставратора

Вопреки первому впечатлению (оба каталога помечены тегом `[RM]`), это **две
независимые работы двух разных людей**:

| | pid 5618698 («Лисной Йожыг») | pid 3048819 («Alias Divas») |
|---|---|---|
| тем в каталоге | 178 | 500 |
| жанровая ниша | классический рок, хард-рок, прогрессив | тяжёлые жанры: дэт/грув/индастриал/металкор |
| мета-поля темы | «Год выпуска», «Аудио кодек» | «Год издания», «Аудиокодек» |
| тип рипа | чаще `image+.cue` | `tracks+.cue` |
| публикация анализа | текстовая таблица DR-метра (62 темы / 515 релизов) | реже текстом: 18 тем / 122 релиза, чаще скриншотами MasVis |
| пересечение по артистам | — | 3 общих артиста из 176 и 499 (Evanescence, Fear Factory, Leaves' Eyes) |

Разные поля мета, разная упаковка, разные жанровые ниши, почти непересекающиеся
каталоги — это два автора с собственными вкусом и инструментами. Значит:

- стратификация «автор» **имеет смысл** (это разные целевые функции);
- отложенная оценка обязана держать 30 % альбомов **каждого** автора вне
  настройки, иначе «универсальность» не проверяется.

Практическое следствие для сбора: у «Лисного Йожыга» цель по DR часто известна
заранее из текстовой таблицы в теме; у «Alias Divas» мастер-релиз придётся
скачивать, чтобы измерить цель (и всё равно это нужно для band-дельт).

## 2. Из чего состоит пара

```
оригинал (необработанное издание, CD 16/44)
    └─► фичи (DR/crest/RMS/peak/clip/30 полос 1/3-окт)   ─┐
                                                        ├─► дельты = обучающая строка
мастер-реставрация [RM] того же альбома                  ─┘
    └─► фичи, эксцерты (для слуховых тестов)
```

Ключ пары — `{restored_topic_id}/rel{idx}`. Обязательные условия:
один и тот же альбом и издание (совпадение каталожного номера из «Исходное
издание»), лосслесс-источник, не винил/SACD/hi-res (другой мастеринг),
не бутлег/лайв-запись вместо студийника.

## 3. Пайплайн сборки

Что уже бесплатно (без скачивания мастер-релиза): `scripts/master_targets.py`
собирает из тем `corpus/master_targets.jsonl` — **637 релизов / 8104 трека** с
опубликованным анализом мастера (DR/Peak/RMS по трекам, crest_tt = peak − rms):

- медиана crest_tt мастера 12.60 (sd 1.58, разброс 8.7…29.7);
- official DR релиза: медиана 11, разброс 8…13;
- по авторам: Лисной Йожыг 515 релизов (медиана crest_tt 12.87), Alias Divas 122 (12.24);
- декады: 70-е 20, 80-е 70, 90-е 87, 2000-е 130, 2010-е 201, 2020-е 127.

Это цель «до» измерения исходника; дельты появляются после сборки пар.

```
scripts/dataset_plan.py topics   # страницы тем мастеров → corpus/restored/{tid}.json
                                 #   releases[] + текстовая таблица DR мастера (если есть)
scripts/dataset_plan.py match    # пул кандидатов на артиста (1 поиск вместо 1 на релиз)
                                 #   → corpus/dataset_plan.jsonl  (matched/weak/no_original)
scripts/dataset_plan.py report   # сводка: объём, декады, master DR, доля дискографий
scripts/dataset_fetch.py --dry-run   # что именно будет качаться (выбор файлов)
scripts/dataset_fetch.py --go        # Transmission: файловый отбор + старт
```

Особенности матчинга:
- пул кандидатов берётся из «Исходник для обработки» в теме мастера, иначе по
  имени артиста; для промахов — точечный поиск «артист + альбом»;
- скоринг: совпадение альбомной части заголовка (после первого « - »), года,
  каталожного номера; штрафы за винил/DSD/hires/бутлег/лайв-подмену/MP3;
- **CD-дискография артиста** — легальный кандидат (`matched_graphy`): нужный
  диск выбирается уже по списку файлов раздачи. Это часто единственный
  CD-источник: у Accept, например, почти все альбомы на rutracker только в LP,
  а CD-издания лежат в теме «Дискография (114 CD)»;
- финальную проверку даёт скачивание: сопоставление файлов с трек-листом
  мастера (номер + токены названия), порог 60 %; ниже — пара отбрасывается.

## 4. Дискография как источник и «качать только нужное»

Transmission RPC (`rnext/transm.py`) позволяет добавить раздачу на паузе,
получить список файлов и снять ненужные (`files-unwanted`), затем стартовать.
Так из темы-дискографии качается **только нужный диск/альбом**, а лайвы, бонусы
и сканы не качаются вообще:

```
torrent-add(paused) → torrent-get(files) → match_tracks() → torrent-set(files-unwanted) → torrent-start
```

Два режима отбора файлов:
- `tracks` — пофайловый матч с трек-листом мастера (обычные темы);
- `image` — образ + cue берём целиком, режем по cue после скачивания.

**Одна тема — несколько пар.** Тема-дискография обслуживает сразу много пар,
а wanted-набор у раздачи один. Поэтому набор считается КАК ОБЪЕДИНЕНИЕ
нужных файлов по всем парам этой темы (`dataset_fetch.py --repair`),
иначе вторая пара снимала бы файлы первой. То же при повторном добавлении:
`torrent-duplicate` → union с уже выбранным.

Проверка на живой партии: мастер-раздача Anneke van Giersbergen (214 файлов)
дала wanted 25 из 214 (два альбома), Kylie Minogue (360 файлов) — 28 из 360
(два альбома) — скачивается только нужное.

## 5. Хранилище (жёсткий лимит 40 GiB)

```
/media/mydum/Data/Music/restore/dataset/
  plan/…                  не хранится: план лежит в corpus/dataset_plan.jsonl
  raw/<key>/              СЫРЬЁ, транзиент: скачал → извлёк → удалил
  pairs/<key>/meta.json   ids, треки, подобранные файлы, master DR, QC-флаги
  pairs/<key>/features.jsonl   по-трековые фичи обеих сторон (~1.5 КБ/трек)
  pairs/<key>/excerpts/        8–30-с вырезки (громкое место + середина), обе стороны
  features/all.jsonl      объединённая обучающая таблица
  state.jsonl             журнал загрузок (append-only)
```

Три уровня хранения и их цена:

| уровень | на трек (обе стороны) | на пару (~12 треков) | отношение к сырью | влезает в 40 GiB |
|---|---|---|---|---|
| сырьё FLAC (транзит) | ~70 МБ | ~0.8–1.0 ГБ | ×1 | ~30 пар одновременно |
| вырезки 8–30 с | ~3 МБ | ~36 МБ | ×23 | ~900 пар |
| фичи | ~1.5 КБ | ~18 КБ | ×47 000 | практически безлимит |

Политика: **фичи — навсегда, вырезки — навсегда (они нужны для слуховой
валидации и residual-тестов), сырьё — только под активную задачу.** Ротацию
держит `rnext/workspace.py` (бюджет 40 GiB, `remaining_bytes()` перед каждой
загрузкой).

## 6. Как на этом улучшается пайплайн

1. **Цель `target_dcrest` как функция материала.** Сейчас это константа 4.6
   плюс классовые правила. По датасету строится модель
   `Δcrest ≈ f(класс, исходный DR/crest/RMS, жанр, эра, автор)` — сначала
   таблица средних по стратам, затем малоразмерная регрессия со случайным
   эффектом альбома (важно: разброс внутри альбома ~0.3 дБ не объясняется
   скалярами).
2. **Слепой предиктор (главный открытый TODO).** 500+ пар дают ~6000 треков
   с известной целью — этого достаточно, чтобы цель перестала быть константой.
3. **Спектральная подгонка.** Band-дельты по корпусу дают средний «тёплый»
   тилт автора; после набора пар можно решить, вводить ли EQ-слой (сейчас вне
   скоупа v1) и как его параметризовать по жанру/эре.
4. **Пороги приёмки и QC-гейты** калибруются по распределениям (а не по 3
   альбомам), включая residual-тест и ABX-наборы.
5. **Отложенная оценка**: 30 % альбомов каждого автора — hold-out; базовая
   линия из четырёх систем (оригинал, оригинал с выравненной громкостью, наш
   пайплайн, мастер), метрики пер-трековыми распределениями + слепой слух.

## 7. Открытые вопросы

- **Объём**: для ±0.15 дБ по альбомной цели нужно ~20–30 альбомов в страте;
  для предиктора по треку — 300–600 треков (у нас сейчас 37).
- Деклип не откалиброван на реально клипованном материале (эра 1990-х, LP-рипы
  не берём — тогда CD-издания с клипом).
- Тёплая EQ-подкраска мастера измерена на одном альбоме — нужен band-датасет.
- Второй *независимый* реставратор подтверждён (Alias Divas), но его ниша
  смещена к тяжёлым жанрам; для покрытия «классики» есть только Лисной Йожыг.
