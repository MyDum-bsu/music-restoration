# E2 · Versioned corpus and benchmark runner protocol

Spec: E0 charter + spec v1 (2026-11-23), section 4. This document fixes the
custodian, the split policy, the metric definitions and the pilot plan that E2
must register before the sealed tier may run. Status: pilot values **unset** —
the sealed tier is blocked by construction until they are registered.

## Tiers

| Tier | Manifest | Contents | Distribution |
|---|---|---|---|
| smoke | `corpus/smoke-v1.json` | Deterministic synthetic stereo pairs (synth/v1), negative controls | Public: generator + hashes only |
| dev | `corpus/dev-v1.json` | Synthetic dev split train/eval/control, licensed for local+Colab | Public method + hashes, publication off |
| sealed | `corpus/sealed-v1.json` | Custodian-held descriptors; no audio bytes in the repo | Custodian only, until E5 |

Synthetic cases are never committed as audio. `research/build_corpus.py`
regenerates byte-identical WAV/mask files from the pinned `synthesis` block
(generator id, seed, rate, seconds, operator, parameters); the manifest pins
each file's sha256+bytes, so any platform or code drift fails validation.

## Custodian

- Sealed bytes are marked `held_by: custodian` in `sealed-v1.json`. They are not
  distributed, not regenerated by the builder and never appear in a dev report:
  the runner drops `sealed: true` cases unless `--custodian-release` is passed.
- Custodian: appointed by the owner (see `custodian` block in the sealed
  manifest). Custodian alone holds the sealed inputs and the blind-panel
  randomisation keys; release happens only after the E4 freeze.
- Any later edit to the sealed set or protocol requires a new dataset_version
  and a new custodian-held set — no re-tuning on opened results.

## Split policy

Split is defined by group keys: `take`, `fingerprint`, `session`, `artist`,
`album`, `stem_family`. The validator (`research/corpus_v1.py`) rejects a
manifest where any group value appears under two different `split` values —
no slices of one recording, session, artist, album or stem/master family may
land in different splits. Strata of different scale/carrier are kept as
separate cases/profiles.

## Rights model

Each case declares boolean rights for `local_inference`, `colab`, `training`,
`listening`, `publication`. The runner takes `--operation`; a case whose right
is false for the requested operation fails validation and cannot run. Sealed
cases deny every operation until custodian release.

## Metric definitions

- `fixed_gain_sdr_db` — clean energy / reconstruction error energy at unity
  gain, float64, no time shift.
- `scale_aligned_sdr_db` — same, after the single least-squares gain that maps
  the candidate onto clean. The gain itself (`gain_to_clean`) is stored.
- `masked_fixed_gain_sdr_db` — fixed-gain SDR restricted to the true mask
  (RLE `*.mask` file pinned per synthetic case).
- `numeric_tolerance` (manifest field, default 1e-6 dB) is the documented
  cross-environment tolerance; `compare_reports` applies it to every numeric
  field and requires exact equality of case ids, input sha256 and statuses.
- Abstentions/errors are per-method statuses (`ok`/`error`), never silently
  dropped; `results.json` is finite JSON (`allow_nan=False`).

## Reproducibility

`run_benchmark.py` writes `protocol.json` (manifest sha256, toolchain pin,
implementation file hashes, argv) and `results.json`. Two clean checkouts
running the same manifest must match on case ids, input hashes and statuses,
with metrics inside `numeric_tolerance`. Covered by
`tests/test_corpus_v1.py` via the real CLI, twice.

## Pilot plan (registers before E4 freeze)

Measured on the dev tier only. Sealed stays blocked while any value is null.

| Field | How it is set | Status |
|---|---|---|
| `pilot.sample_size` | n of independent recording clusters needed for 95% CI on the primary SDR claim, estimated from dev variance | unset |
| `pilot.gate_margin_sdr_db` | practically significant SDR margin vs identity/gain-only, from dev pilot | unset |
| `pilot.gate_margin_vs_external_db` | superiority/non-inferiority margin vs strong external DSP, chosen before sealed is seen | unset |
| `pilot.min_coverage` | minimum fraction of defect cases the method may attempt | unset |
| `pilot.cpu_p95_s_per_audio_min` | p95 wall time per audio minute on the reference local CPU | unset |
| `pilot.rss_mb_p95` | p95 peak RSS on the reference machine | unset |
| `pilot.registered_at` | registration timestamp = freeze of the above | unset |

Unset values block `tier: sealed` in `validate_manifest`; dev and smoke run
with the same fields present but null.
