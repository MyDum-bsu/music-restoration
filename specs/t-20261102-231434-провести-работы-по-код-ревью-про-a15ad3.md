## Intent

Запрос просит «провести работы по код-ревью и разбить на задачи и спеки». Разбить нельзя до того, как пункты проверены по коду: часть из них уже сделана, часть сформулирована так, что исполнение сломает работающий конвейер. Эта задача даёт проверяемую основу для всей волны — отчёт `docs/code-review-2026-11-02.md` по 12 пунктам, с вердиктом, доказательством из репозитория и строкой декомпозиции. Кода не касается.

Область риска: только новый markdown-файл. `scripts/restore_per_track.py`, `scripts/finish_release.py`, `scripts/qc_gates.py` заняты фоновым реставрационным конвейером, `/media/mydum/Data` и запущенные процессы (transmission-gtk, lane.py, process_album.sh, supervisor) не трогаются вообще — в этой задаче даже аддитивные правки не нужны.

## Given

- Репозиторий — Python-проект: `rnext/` (библиотека) и `scripts/` (CLI), тесты `python3 -m pytest tests/ -q` (README).
- Два скорера существуют одновременно: `score_candidate` в `rnext/planner.py` (отбор исходного издания, штрафы live/vinyl/hi-res/alt-edition, пороги 80/68) и `score` в `scripts/tracker_hunt.py` (ранжирование качества издания: lossless ±100, источник, DR из топика, логи).
- Часть пунктов постановки указывает на артефакты, которых в репозитории может не быть (`CODING_STANDARDS.md`, `config/workspace.example.json`, `docs/setup.md`, `scripts/rt_browser_refresh.py`).
- В `docs/` нет `architecture.md`, `conventions.md`, `decisions/README.md`; в корне нет `AGENTS.md` — при «сверить пути в документации» это тоже факт ревью.
- Oracle уже лежит в `.factory/integration/oracle/t-20261102-231434-провести-работы-по-код-ревью-про-a15ad3/test_review_report.py` и запускается из корня репозитория.

## When

Воркер читает код и запускает oracle из корня репозитория. Пишет `docs/code-review-2026-11-02.md` со структурой:

```
# Код-ревью music-restoration, 2026-11-02
## Summary
## Findings
### CR-01 … ### CR-12     (Verdict / Evidence / Impact / Effort / Next)
## Decomposition          (| Item | Verdict | Next task | Why |)
## Constraints
```

Каждая секция `### CR-NN` обязана содержать строку `Verdict: <done|open|needs-spec|rejected>` и минимум одну ссылку на существующий путь репозитория; для `done` — `path:line` (либо, для пунктов, добавляющих файл — CR-05/06/08/10 — сам артефакт, который обязан существовать).

## Then

- `docs/code-review-2026-11-02.md` существует, ≥3000 символов, без TODO/TBD/FIXME.
- 12 секций `### CR-01`..`### CR-12`, каждая ровно один раз, лишних id нет.
- Все четыре секции `Summary`, `Findings`, `Decomposition`, `Constraints` на месте.
- Таблица `Decomposition` содержит столбцы Item и Task, строку на каждый пункт, вердикт в строке равен вердикту в секции, `Next task` непустой.
- Секция `Constraints` называет `scripts/restore_per_track.py`, `scripts/finish_release.py`, `scripts/qc_gates.py`, `/media/mydum/Data`.
- `dod` — зелёный; в `git status` единственное изменение — добавленный файл отчёта.

## Forbidden

- Править что-либо, кроме `docs/code-review-2026-11-02.md`: код, `scripts/`, `rnext/`, `tests/`, SKILL.md, конфиги, версию, CI, борд-файлы. Найденные проблемы — строкой в отчёте.
- Трогать `scripts/restore_per_track.py`, `scripts/finish_release.py`, `scripts/qc_gates.py`, `/media/mydum/Data`, любые запущенные процессы; останавливать или перезапускать конвейер.
- Ставить `done` без доказательства в репозитории; выдавать предположение за проверенное; ссылаться на `path:line`, который не открывался.
- Угадывать, какие два SKILL.md имеются в виду в CR-12, и какие файлы содержит CI в CR-09: не нашёл — `needs-spec` с причиной.
- Печатать в отчёт содержимое `.env`, cookies, `cf_clearance`, токены Transmission, любые секреты — только имена файлов.
- Коммитить, пушить, создавать ветки/worktree, заводить задачи на борде, запускать реставрацию или `audio_measure.py` на реальных файлах.
