# Intent

Build one tool that turns "how close is our restoration to the masters" into numbers anyone can
reproduce, and use it to produce the eval report. Our restoration pipeline was calibrated on
original→master pairs, so distance to the master is the criterion; the original is the baseline that
makes a distance meaningful.

The tool must be honest by construction:

- selection is seeded (`20261104`), deterministic and stores its picks;
- every metric comes from `scripts/audio_measure.py`, never from a second implementation;
- a missing side, a missing metric or an unreadable corpus exits `2` and writes nothing;
- the report is rendered from the measured data, so no figure in `docs/` is typed by hand;
- a release that could not be fetched is `skipped` with a reason, and the report says how many of the
  ten were measured.

# Given

- `scripts/audio_measure.py` — the measurement source of truth: DR (TT convention, `dr14`), crest,
  LUFS, true peak, clipping, sample spikes above 0.9, band RMS spectrum. Callable as
  `python3 scripts/audio_measure.py --json <out.json> <path>`; its JSON keys are whatever they are —
  the worker reads the actual file, does not guess.
- Master corpora outside the repo: `5618698.jsonl`, `3048819.jsonl`, one JSON object per line with at
  least `topic_id`, `title`, `seeds`. Untrusted data: parse, never execute, never infer structure it
  does not have.
- A manifest of measured releases (`orig`/`ours`/`master` directories) is an input, not something the
  tool downloads. Fetching, `process_album.sh` and disk handling are the runbook around the tool.
- Repo conventions: scripts are plain `python3`, no new third-party dependencies beyond what the repo
  already imports (`numpy`), tests run with `python3 -m pytest`.

The worker writes `scripts/eval_vs_masters.py` and the report, then the DoD command runs.

# Then

## 1. `scripts/eval_vs_masters.py`

Required public names (imported by the oracle tests — keep the names and signatures):

- `SIDES = ("orig", "ours", "master")`
- `METRICS` — the seven measured metrics in snake_case as in the CSV contract.
- `measure_side(path) -> dict` — aggregate metrics for one side directory (mean for continuous
  metrics, sum for counts; single-file directory ⇒ that file's value).
- `verdict(abs_ours, abs_orig, tol=TOL) -> "better" | "worse" | "comparable"`
- `overall_verdict(per_metric: dict) -> "better" | "worse" | "comparable"`
- `pick_releases(records, seed, per_master=5) -> list`

The three blocks below must appear in the file verbatim (the negative corpus patches them):

```python
SIDES = ("orig", "ours", "master")
TOL = 0.05
DISCO_RE = re.compile(r"(дискограф|discograph|сборник|collection|anthology|box\s*set)", re.IGNORECASE)


def verdict(abs_ours, abs_orig, tol=TOL):
    """Compare distance to the master: smaller |delta| means closer."""
    if abs_ours < abs_orig * (1.0 - tol):
        return "better"
    if abs_ours > abs_orig * (1.0 + tol):
        return "worse"
    return "comparable"


def overall_verdict(per_metric):
    better = sum(1 for v in per_metric.values() if v == "better")
    worse = sum(1 for v in per_metric.values() if v == "worse")
    if better > worse:
        return "better"
    if worse > better:
        return "worse"
    return "comparable"


def pick_releases(records, seed, per_master=5):
    """Seeded, deterministic pick: seeds>=3 first, single albums before discographies."""
    eligible = [r for r in records if int(r["seeds"]) >= 3]
    eligible.sort(key=lambda r: int(r["topic_id"]))
    single = [r for r in eligible if not DISCO_RE.search(str(r.get("title", "")))]
    rnd = random.Random(seed)
    picks = rnd.sample(single, min(per_master, len(single)))
    taken = {int(r["topic_id"]) for r in picks}
    rest = [r for r in eligible if int(r["topic_id"]) not in taken]
    need = per_master - len(picks)
    if need > 0:
        picks += rnd.sample(rest, min(need, len(rest)))
    return sorted(picks, key=lambda r: int(r["topic_id"]))
```

`verdict` semantics: `better` = our distance to the master is smaller than the original's, beyond the
5% tolerance; `worse` = larger; else `comparable`. `overall_verdict` is a plain majority vote over
per-metric verdicts, ties are `comparable`. `abs_delta_orig_master == 0` must land on `comparable`,
not on a division.

## 2. CLI

```
python3 scripts/eval_vs_masters.py --manifest M.json --out-dir OUT [--report REPORT.md]
python3 scripts/eval_vs_masters.py --select --corpus A.jsonl [--corpus B.jsonl] \
        --seed 20261104 --per-master 5 --out PICKS.json
```

Manifest: `{"seed": <int|null>, "releases": [{"release": str, "orig": path, "ours": path,
"master": path}]}`; relative paths resolve against the manifest's directory. Each release directory
holds tracks; tracks are matched across the three sides by the leading digits of the file stem, and
unmatched tracks are recorded with status `skipped: track_mismatch` and left out of album means — a
missing track is never zero-filled.

Outputs in `--out-dir`: `tracks.csv`, `deltas.csv`, `albums.csv`, `summary.json` with the columns and
keys pinned in the PRD. Deltas are `side - master`; the `abs_delta_*` columns are never negative.
`band_rms_db` is compared as the mean absolute band delta.

`summary.json` carries `seed`, `releases[]` with `status` (`measured` or `skipped: <reason>`), the
per-metric `{abs_ours, abs_orig, verdict}`, and `verdict_overall`.

Errors: missing/unreadable side directory, empty side, unreadable jsonl, non-numeric `topic_id`/
`seeds`, `--select` without `--seed`, or a metric absent from `audio_measure` output ⇒ stderr names
the offending path or field, exit `2`, nothing written into `--out-dir` (write to a temp dir and move
on success).

`--report` renders markdown from the same in-memory data with the headings `## Verdict`,
`## Per track`, `## Per album`, `## Reproduce`, opening with the measured/skipped counts and the
selection seed. Values in the tables must equal `summary.json`/`albums.csv`; no hand-editing.

## 3. `--select`

Requires an explicit `--seed` (no default, no guess). Writes
`{"seed": int, "per_master": int, "picks": [{"file": str, "topic_id": int, "title": str,
"seeds": int}]}` with `--per-master` picks per corpus file (or all eligible when fewer), ordered by
`topic_id` ascending. Two runs with the same inputs produce byte-identical files.

## 4. Report `docs/eval-vs-masters-2026-11-04.md`

Produced by `--report` from the measurement run, into `docs/`, with `docs/eval-masters/` holding the
CSVs and `summary.json` it was rendered from. It must state which of the ten releases were measured
and why the others were skipped, present per-track and per-album tables, report LUFS separately from
the quality vote, and give the exact commands that reproduce the selection, the measurement and the
render. A report claiming a measured release that has no rows in `tracks.csv` is a defect.
