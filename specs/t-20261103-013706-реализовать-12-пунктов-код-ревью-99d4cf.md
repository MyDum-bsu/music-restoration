# Spec: 12 пунктов код-ревью 2026-11-02

Контракт задан файлом `oracle/<ID>/test_review_contract.py` — 12 проверок, по одной на пункт
`docs/code-review-2026-11-02.md`. Проверки не ходят в сеть, не читают `/media`, не пишут вне `tmp`.

## Intent

Сделать продукт пригодным для чужого пользователя и защитить агент-критичный код: один скорер
релизов, скиллы без машинных путей, тесты на парсерах, CI, документированный вход, версия 2.1.
Реставрационный конвейер в это время может работать — поэтому `qc_gates.py` правится только
аддитивно, а `restore_per_track.py` и `finish_release.py` не трогаются вовсе.

## Given

- `rnext/planner.py` содержит `score_candidate`, `scripts/tracker_hunt.py:225` — независимый `score()`.
- `skills/release-restore/SKILL.md:10` хардкодит `R=/media/mydum/Data/Music/restore`, `S=~/Desktop/projects/...`; `skills/release-restore/SKILL.md:62` ссылается на `scripts/status_report.py` (файл лежит в `research/`).
- `scripts/qc_gates.py:110-112` считает спайки абсолютно, режима `--orig` нет.
- `scripts/release_batch.py` не помечен устаревшим; `pyproject.toml` = 2.0.0; `.github/` отсутствует; `docs/setup.md`, `CODING_STANDARDS.md`, `config/workspace.example.json`, `scripts/rt_browser_refresh.py`, `tests/test_parsers.py`, `tests/test_qc_gates_spikes.py` отсутствуют.
- `tests/` содержит только DSP-тесты.

## When

Исполнитель проходит 12 пунктов ревью, каждый — минимальной правкой в своей области, и приводит
`dod` в зелёное состояние.

## Then

1. `rnext/planner.py` экспортирует `def score_facts(...)` — единственное место, где заданы критерии выбора релиза. `scripts/tracker_hunt.score()` вызывает `score_facts` и не определяет собственных весов; `def score_candidate` в `tracker_hunt.py` отсутствует.
2. Ни в одном `skills/**/SKILL.md` нет подстрок `/media/`, `/home/<user>/`, `Desktop/projects`. Путь данных описывается словами: «из `config/workspace.json`» / значение из `rnext.workspace`.
3. Каждая ссылка в скиллах вида `scripts|research|rnext|config|tests/<файл>` указывает на существующий файл (`scripts/status_report.py` → `research/status_report.py` и т.п.). Глобы и `~/.config/...` не проверяются.
4. `scripts/qc_gates.py` получает опциональный `--orig <dir>`: с ним спайк-гейт FAIL'ит только если в результате спайков больше, чем в источнике; без него поведение прежнее. `python3 scripts/qc_gates.py --help` выходит 0 и печатает `--orig`. Поведение покрыто `tests/test_qc_gates_spikes.py`.
5. `tests/test_parsers.py` проверяет `parse_music`, `parse_video`, `parse_topic_page`, `parse_dr_table` на сохранённых HTML-фикстурах в `tests/fixtures/` (минимум 4 файла). Тесты фиксируют текущее поведение; найденный баг парсера — строка в отчёте, не правка парсера.
6. `docs/setup.md` — чек-лист входа: зависимости, `config/workspace.json`, Transmission RPC, куки rutracker (`cf_clearance`), первая реставрация. `scripts/rt_browser_refresh.py` существует, отвечает на `--help`, пишет куки туда, откуда их читает `rnext/rtclient.py` (без правок `rtclient.py`).
7. `scripts/release_batch.py` помечен deprecated в docstring и печатает deprecation в stderr, называя замену `scripts/restore_per_track.py`; поведение скрипта не меняется, файл не удаляется.
8. `CODING_STANDARDS.md` — рабочий стандарт: слои (`rnext/` — ядро, `scripts/` — тонкие CLI), тесты через pytest, запрет машинных путей в скиллах, дисциплина секретов.
9. `.github/workflows/*.yml` ставит зависимости и запускает `pytest tests/`.
10. `config/workspace.example.json` — валидный JSON, ключи как в `config/workspace.json`, ни одного машинного пути; шаблон упомянут в `docs/setup.md`/`README.md`.
11. `pyproject.toml` version >= 2.1.
12. Frontmatter всех `skills/**/SKILL.md` парсится как YAML (значения с `: ` закавычены).
13. `dod` зелёный; при применении `oracle/negative/<ID>/kit.patch` — красный ровно на `no_machine_paths_in_skills` и `skill_referenced_paths_exist`.

## Forbidden

- Править `scripts/restore_per_track.py`, `scripts/finish_release.py`, `rnext/rtclient.py`, `rnext/rttopic.py`, `research/**`, `app/**`, `install.sh`.
- Любая неаддитивная правка `scripts/qc_gates.py`: переименование существующих функций/флагов, изменение дефолтного порога спайков, изменение формата отчёта.
- Трогать `/media/mydum/Data`, `config/workspace.json`, `~/.config/music-restoration/`, запущенные процессы реставрации.
- Удалять `scripts/release_batch.py` вместо деприкейта.
- Чинить парсеры или DSP «по пути»: расхождение с фикстурой — отчёт, не правка.
- Подменять проверки контракта: менять `oracle/<ID>/*`, ослаблять проверки, добавлять `xfail`/`skip`, гонять `dod` с исключёнными тестами.
- Коммитить `skills/_negative_probe/` или иной мусор negative-контроля.
- Добавлять в CI линтеры/type-check сверх pytest; менять зависимости ради тестов, если хватает stdlib + pytest.

## Notes for the worker

- `live_model.command` — второй вход к тому же контракту (печатает `INVARIANT <name>: PASS|FAIL`, exit != 0 при FAIL). Он импортирует проверки из `test_review_contract.py`, поэтому при добавлении проверки правьте только oracle-файл и map инвариантов в пробе.
- Negative-контроль: применить `kit.patch` к корню репозитория, прогнать `dod`, увидеть красное на двух названных проверках, откатить патч. `kit.patch` только добавляет новый файл, поэтому прикладывается к любой базе.
- Если PyYAML в окружении отсутствует, проверка frontmatter валидирует форму блока (кавычки вокруг значений с `: `); контракт от наличия пакета не зависит.
