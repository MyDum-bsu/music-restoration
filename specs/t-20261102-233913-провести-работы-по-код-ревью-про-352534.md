## Intent

Закрыть пункты ревью `docs/code-review-2026-11-02.md`, не меняя поведение золотого
пути: одно ранжирование качества релиза, портируемые скиллы, гейт спайков с
baseline источника, покрытие парсеров тестами, документированный вход для чужой
машины, гигиена репозитория (CI, стандарты, версия, шаблон конфига).

Отчёт ревью существует и является входом задачи. Задача правит продукт, а не
переписывает ревью.

## Given

- `rnext/planner.py::score_candidate(row, artist_tokens, album_tokens, year, codes, own_poster) -> dict`
  — паросочетание мастер→оригинал по токенам/году/каталожному номеру/постеру.
- `scripts/tracker_hunt.py::score(f) -> (float, list[str])` — оценка качества версии
  по разобранным фактам (`kind`, `lossless`, `source`, `bits`, `dr_published`,
  `has_log`, `has_scans`, `image_cue`, `video.resolution/source/codec/hdr/audio/subs`,
  `book.format/text_layer`). Это единственное место, где живут веса качества.
- `scripts/qc_gates.py` считает спайки абсолютно: у горячего мастера
  (748 спайков в источнике → 35 в реставре) гейт FAIL'ит лучший результат.
- `skills/**/*.md` содержат `/media/mydum/Data/Music/restore`, `~/Desktop/projects/...`
  и устаревшую ссылку `scripts/status_report.py` (файл — `research/status_report.py`).
- `tests/` покрывает только DSP.
- Нет `docs/setup.md`, `CODING_STANDARDS.md`, `.github/workflows/`, `config/workspace.example.json`;
  `pyproject.toml` = 2.0.0 при истории v2.1; в двух `SKILL.md` незакоммиченный
  YAML-фикс кавычек.
- Фоновая реставрация прямо сейчас использует `scripts/qc_gates.py`,
  `scripts/restore_per_track.py`, `scripts/finish_release.py`; `/media/mydum/Data`
  и процессы (`transmission-gtk`, `lane.py`, `process_album.sh`, supervisor) не трогать.

## When

Исполнитель работает в отдельном worktree, фазами, в порядке ниже; после каждой
фазы `python3 -m pytest tests/ -q` остаётся зелёным.

1. **Единый скорер.** В `rnext/planner.py` появляется
   `score_facts(facts: dict) -> tuple[float, list[str]]` — перенос тела нынешнего
   `scripts/tracker_hunt.py::score` без изменения весов, порядка пояснений и
   поведения на неполных словарях. `scripts/tracker_hunt.py::score` становится
   делегацией (`from rnext.planner import score_facts` … `return score_facts(f)`),
   таблицы весов из скрипта удаляются. Обратной зависимости `rnext → scripts` нет.
2. **Скиллы без машинных путей.** Во всех `skills/**/*.md` абсолютные пути этой
   машины заменяются на «путь из `config/workspace.json`» / `rnext.workspace.data_root()`;
   все ссылки на файлы сверяются с деревом (`status_report` → `research/status_report.py`).
   YAML-кавычки из dirty-дифа попадают в коммит.
3. **Гейт спайков.** `scripts/qc_gates.py` получает опциональный `--orig`: baseline
   спайков берётся из источника; FAIL только если в выходе спайков строго больше,
   чем в источнике. Без `--orig` — прежний код и прежний текст вердикта.
   Если baseline посчитать нельзя — явная ошибка, не PASS и не baseline=0.
4. **Тесты парсеров.** `tests/` получает сохранённые HTML-фикстуры и тесты на
   `parse_music`, `parse_video` (из `scripts/tracker_hunt.py`), `parse_topic_page`,
   `parse_dr_table` (из `rnext/rttopic.py`). Тесты офлайновые, без сети и без
   `/media`, с явными ожиданиями, включая случай отсутствующего блока в HTML.
5. **Вход для чужой машины.** `docs/setup.md` (зависимости, `config/workspace.json`,
   Transmission+RPC, куки rutracker, обновление `cf_clearance`) и
   `scripts/rt_browser_refresh.py` (обновление `cf_clearance` через браузер;
   `--help` работает без браузера; без браузера/профиля — понятная ошибка).
6. **Легаси и гигиена.** `scripts/release_batch.py` помечается устаревшим в
   docstring и `--help` (или удаляется); `CODING_STANDARDS.md` в корне;
   `.github/workflows/ci.yml` с `pytest`; `config/workspace.example.json` — валидный
   JSON без машинных путей; `pyproject.toml` version → 2.1.x; при желании —
   секция «Статус пунктов» в `docs/code-review-2026-11-02.md`.

  среди `rnext/**/*.py`, `scripts/**/*.py`, `research/**/*.py` — в
  `rnext/planner.py`.

- В `skills/**/*.md` нет `/media/`, `/home/`, `Desktop/projects`, `X:\`;

- `scripts/restore_per_track.py`, `scripts/finish_release.py`, `config/workspace.json`

## Forbidden

- Любая правка `scripts/restore_per_track.py`, `scripts/finish_release.py`,
  `config/workspace.json`, `rnext/dsp*`, `rnext/rtclient.py` (кроме случая, когда
  браузерный фоллбэк требует нового модуля — тогда новый файл, не правка RPC-клиента).
- Изменение существующих флагов/дефолтов/вывода `scripts/qc_gates.py`; удаление
  или переименование гейтов; `--orig`, включённый по умолчанию.
- Переписывание весов качества при переносе `score` в `rnext/planner.py`: значения,
  условия и порядок пояснений переносятся дословно.
- Сведение `score_candidate` и `score_facts` в одну сигнатуру; импорт `scripts/*`
  из `rnext/*`.
- Запуск реставрации, обращение к `/media/mydum/Data`, к Transmission RPC, к сети
  (rutracker) в тестах, оракуле или PBT; остановка/перезапуск фоновых процессов.
- Секреты и куки в репозитории: `cf_clearance`, cookies, UA, RPC-пароль — только
  в `~/.config/music-restoration/`, в `docs/setup.md` — инструкция, не значения.
- Правка `oracle/**` и `oracle/negative/**`, `docs/code-review-2026-11-02.md`
  в части уже написанных выводов ревью.
- Заглушки вместо реализации: `TODO`, `pass`-тесты, `assert True`, фиктивные
  фикстуры, фоллбэк вместо ошибки при недоступном baseline.
- Коммиты в `main`/`dev` напрямую; выход за `allowed_paths`.
